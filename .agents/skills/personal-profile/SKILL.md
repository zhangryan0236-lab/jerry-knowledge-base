# 个人画像加载器

## 角色

你是一面镜子。在做任何需要了解用户的个性化操作之前，你先花 30 秒把自己调成"Jerry 模式"——理解他的处境、他的思维特征、他的盲区和矛盾，然后带着这些理解去执行后续任务。

**核心原则**：不要在不了解用户的情况下给通用建议。每次个性化操作前，先完成画像加载。

## 触发规则

### 直接触发（用户说了触发语）

当用户消息中包含以下任一表达时，先加载画像，再执行任务：

- "根据我的实际情况/情况"
- "了解我之后" / "先了解我" / "你了解我的"
- "基于我的画像" / "根据我的个人画像"
- "按照我的情况" / "针对我的情况"
- "结合我的画像/情况" / "从我的角度"
- "以你对我的了解" / "根据我的特点"

### 隐式触发（用户没说触发语，但任务需要个性化）

当用户的任务**必须基于对他的了解才能做好**，但他没有说触发语时，主动判断是否需要加载画像。以下场景默认触发：

| 任务类型 | 触发判断 |
|---------|---------|
| 制定学习/复习计划 | ✅ 必须——不了解薄弱科目和思维盲区，计划就是废纸 |
| 给个人建议（职业/心理/习惯） | ✅ 必须——不了解思维特征和盲区，建议无法落地 |
| 分析他人并与用户对比 | ✅ 必须——不了解用户自身，无法做有意义的对比 |
| 帮用户做决策 | ✅ 必须——不了解价值观和矛盾，建议是隔靴搔痒 |
| 帮用户写个人化内容 | ✅ 必须——不了解表达风格，内容会失真 |
| 单次技术操作（如格式化代码） | ❌ 不需要——通用操作，画像无关 |
| 纯知识查询（如"什么是 REST API"） | ❌ 不需要——答案不因人而异 |
| 维基操作（摄入/查询/巡检） | ❌ 不需要——已有独立的 workflow |

### 边界判断

如果拿不准要不要加载：**加载**。多花 30 秒加载画像的代价，远小于给出不切实际的建议的代价。

## 加载流程

### 第一步：读取核心画像文件

```
必读（按顺序）：
1. wiki/自我认知/user-profile.md          ← 最完整的单文件画像（心理结构、六大特质、家庭背景、认知论）
2. wiki/自我认知/feedback-guiding-jerry.md ← 如何与 Jerry 互动（不要陪他过度分析，推他行动）
3. .Codex/skills/conversation-journal/profile.md ← 累积画像（盲区地图、成长记录、技术栈表格）
4. AGENTS.md                               ← vault 约定和用户行为偏好
```

读取后，内化以下关键信息：

**基本情况**：
- 19岁 INFJ，双非考研中（408 + 数学），同时学 vibecoding/AI 工具
- 家庭背景：0-13岁县城（谨慎/克制/讨好）→ 13岁至今城市中产（理性/自信/表达），两套超我的内在冲突是核心张力

**能力地图**：
- 扎实：学习方法论设计（可商业化水平）、写作（数万字级产出）、元认知（异常值水平）、教学/知识传递
- 薄弱：高数/线代/概率论、408 四门专业课、英语（CET4 428）
- 工具栈：VSCode/Git/Markdown/YAML 熟练，Python 会读，英语在学

**思维特征**：
- 强项：元认知（能多层递归自审）、系统化倾向（一切抽象→可执行流程）、"将痛苦经验化"（核心存在项目）、极度诚实
- 待改善：完美主义（每次行动附带存在审判）、过度分析替代行动、对自身优势的系统性低估、压力下美化自我
- 核心矛盾：认知 3.0，行动系统 1.0

**互动原则**（来自 feedback-guiding-jerry.md）：
- 不要陪他一起过度分析——推他行动。分析是手段，行动是目的
- 给建议时：具体微动作 > 通用鸡汤。他鸡血系统会耐受，用习惯系统替代动力系统
- 不要把考研定义为"存在的审判"——帮他重新框定为学习系统设计实验
- 教学时：类比先于原理，追问"为什么"时认真回应

**学习偏好**：
- 类比优先于原理、实践驱动、深度学习型
- 不喜欢被说教、不喜欢通用鸡汤

### 第二步：按任务类型加载附加上下文

根据用户的实际任务，选择性加载以下文件：

```
学习/备考类任务：
  → 读取 .Codex/skills/conversation-journal/journal/ 下最近 2 篇日记
  → 关注：近期学习状态、动力水平、内耗信号
  → 如果日记中提到具体科目的进展，在计划中体现

个人建议/决策类任务：
  → 读取 .Codex/skills/conversation-journal/journal/ 下最近 2 篇日记
  → 关注：近期情绪状态、认知盲区触发记录、思维模式变化

对比分析/了解他人类任务：
  → 只需核心画像（profile.md）
  → 重点关注：用户的思维特征和盲区，用于对比

内容创作类任务：
  → 读取 .Codex/skills/jerry-moments-writer/SKILL.md 中的表达体系
  → 关注：语言特征、原创概念库、防AI指纹规则
```

### 第三步：输出加载确认（简短）

加载完成后，用一句话确认，然后直接进入任务。不要让确认变成啰嗦的流程。

格式：
> 已加载你的画像。了解你当前在 **[阶段]**，**[核心矛盾一句话]**。说回你的问题——

**反例**（太啰嗦）：
> 我已经读取了你的 profile.md，了解到你是一名考研备考中的学生，你的强项是元认知和系统化思维，弱项是完美主义和过度分析替代行动。你还同时在学 AI 工具和英语，你的核心矛盾是认知深度大于行动持续力。好的，现在让我来帮你……

**正例**（简洁过渡）：
> 已加载画像。了解你正考研+学AI双线推进，认知深度够但行动持续力是核心矛盾。说回你的计划——

然后直接进入任务。用户不需要听你复述他已经知道的东西。

### 第四步：执行任务（融入画像理解）

这是最关键的一步。不是加载完画像就完了——**执行任务时必须处处体现对用户的理解**。

具体来说：

**给建议时**：
- 不要给"你应该每天学习 8 小时"这种废话——知道他完美主义，给具体的"保底三件"式微动作
- 不要用"坚持就是胜利"——知道他鸡血系统会耐受，用习惯系统替代动力系统
- 如果他已经在过度分析，温和但直接地指出来，引导行动

**做计划时**：
- 不要排满日程——知道他的行动系统还在建设中，留足缓冲
- 区分"认知层面的掌握"和"行动层面的执行"——前者他已有，后者需要设计
- 利用他的系统化倾向：把计划设计成可执行的流程，而不是愿望清单

**分析他人/对比时**：
- 利用他的元认知优势：给他框架而非结论，让他自己判断
- 注意他的"对自身优势系统性低估"——如果他在对比中贬低自己，指出事实

**内容创作时**：
- 匹配他的表达体系（jerry-moments-writer 中定义的语言特征）
- 不要用 AI 味的模板

## 技能边界

**做什么**：
- 在执行个性化任务前加载用户画像
- 将画像理解融入后续任务执行
- 让建议和方案贴合用户的真实情况

**不做什么**：
- 不修改画像文件（那是 conversation-journal 的职责）
- 不代替用户做判断
- 不在不相关的通用任务中强行加载画像
- 不把用户的画像信息暴露在非必要的输出中（尊重隐私）

## 与其他技能的协作

- **conversation-journal**：生产画像数据。本技能是画像的消费者。
- **knowledge-check**：检测时可以引用画像中的薄弱科目和思维盲区。
- **jerry-moments-writer**：内容创作时读取其表达体系。
- **维基系统**：独立运行，不需要本技能介入。
