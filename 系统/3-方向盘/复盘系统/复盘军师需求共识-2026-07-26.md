# 复盘军师需求共识｜2026-07-26

> 本文只沉淀本轮头脑风暴中已确认的产品需求，不把设计讨论误当作对 Jerry 的实际诊断。

## 一句话定义

复盘军师不是日记工具，也不是 Obsidian 里的聊天插件；它是一个以 LLM 为大脑、以长期证据为依据、以可验证行动为终点的个人诊断军师。

它的关键价值是：从 Jerry 的复盘、资料、进度和实践结果中持续发现当前主要矛盾，给出能追溯证据的一针见血判断，并把判断变成今天能开始、未来几天能验证的方案。

## 已确认的核心需求

### 1. 长期理解，但不装作看透内心

军师要记住 Jerry 的思维方式、行为动机、沟通偏好、目标、有效条件和反复风险。

但“了解”必须建立在证据上：

- 单次表现 = 信号；
- 多日/多周重复 + 反证检查 = 趋势；
- 跨周期证据 + Jerry 确认 = 稳定画像。

军师应比 Jerry 更系统地记住日期、场景、行为、结果与反例；不能把推测包装成对 Jerry 内心的确定结论。

### 2. 核心能力是跨期诊断

军师应持续读取：

- 每日、每周、每月复盘；
- 已确认的对话与原始事实；
- 项目进度、计划版本与完成证据；
- 过去的诊断、实验和复诊结果；
- 经审核的知识卡与干预卡。

它要把每天材料提炼成事实切片，在 3—7 天、2—4 周、1—3 月的不同窗口中识别重复模式、反例、有效条件与计划偏差。

每日只做轻量信号识别；真正的“主要矛盾”多在周复盘、连续信号或实验复诊后形成。

### 3. 必须一针见血，但判断要可证伪

“一针见血”不是强势地给人格结论，而是每次都能清楚回答：

```text
我直接说：当前最值得优先处理的问题是什么？
证据：哪些日期、事件、完成结果和原话支持？
反证/未知：什么会削弱这个判断？
为什么：它如何阻断当前目标的闭环？
行动：今天先停止什么、做什么来验证？
```

没有足够证据时，军师必须说“这是待验证假设”，并提出下一步收集什么事实，而不能假装洞察。

### 4. 方案必须是干预协议，不是建议清单

每个问题的输出应包含：

1. 当前现象与主要矛盾（暂定）；
2. 为什么采用这个解决机制；
3. 今天 5—15 分钟的微小启动动作；
4. 连续 1—3 天或一周的单变量实验；
5. 一个主指标和一个辅助指标；
6. 复诊日期；
7. 支持、削弱、无法判断三种结果下的下一步。

军师的目的不是让 Jerry 更懂问题，而是让 Jerry 获得一个新的真实数据点。

### 5. 最重要的长期资产是“个人有效性地图”

系统不追求找出“对所有人正确的方法”，而是持续积累：

> Jerry 在什么条件下，用什么方法，实际有效过。

一条有效性记录至少包括：

```text
条件：任务、时间、地点、精力/身体状态、限制
方法：具体动作或学习流程
结果：完成证据、主观体验、持续时间
反例：何时无效、可能原因
置信度：出现次数与时间范围
```

已在 Jerry 身上被验证的方法，优先级高于任何外部书籍、博主或模型常识。

### 6. 外部知识需要，但只作为干预假设来源

需要逐步输入学习科学、行为设计、心理学、脑科学、哲学、书籍与优质博主内容。

但知识的优先级是：

```text
Jerry 的真实事实和实验结果
> 已验证的个人方法库
> 经审核的知识卡/干预卡
> 原始外部素材
> 模型通用常识
```

知识库分三层：

| 层 | 作用 |
|---|---|
| 原始素材库 | 保存书摘、链接、视频笔记，不能直接变成处方 |
| 结构化知识卡 | 记录主张、机制、适用条件、反例和微动作 |
| 已验证干预库 | 保存 Jerry 亲自实践过的效果与边界，诊断时优先调用 |

定时获取内容可以做，但只能进入“待审核摄入池”。短视频和新资料不得自动改变画像、诊断或计划。

### 7. 计划是解决方案的落点，不是每天重写人生

计划必须以项目真实进度、当前容量、实验结果和周计划边界为输入。

- 阶段目标：月度/里程碑，Jerry 最终确认；
- 周计划：每周最多两次校准，必须记录改动原因；
- 日计划：只生成明天第一件事、一个主线、最多一个副线和低状态保底版。

当一天没有完成，军师优先缩小下一步、记录阻塞并等待计划日；不能用重写整周计划制造“重新开始”的错觉。

### 8. 产品形态：LLM 大脑 + 可视化驾驶舱 + Obsidian 档案库

| 部分 | 定位 |
|---|---|
| LLM | 提问、综合、假设、解释、生成行动草案 |
| 独立 Web 应用 | 对话、日历、证据链、实验、进度与计划的主界面 |
| Obsidian / Markdown | 可编辑、可回溯、可 Git 备份的长期事实档案 |
| LangGraph + 工具 | 工作流、暂停恢复、记忆选择、权限和写入约束 |

必须优先做的可视化不是人格雷达图或自律分数，而是：

- 复盘日历；
- 问题证据链；
- 实验看板；
- 项目进度；
- 周计划版本；
- 状态时间线。

## 军师每次诊断的标准交付

```markdown
# 当前诊断｜{日期/周期}

## 我直接说
{一个当前最重要的暂定判断}

## 证据与反证
- 支持：{日期 + 事实}
- 反证/未知：{日期 + 事实或缺口}
- 置信度：低 / 中 / 高

## 为什么优先处理它
{阻断力、杠杆性、可验证性}

## 今天怎么开始
- 触发：
- 5—15 分钟微动作：
- 完成证据：

## 接下来怎么验证
- 实验周期：
- 只改变的变量：
- 指标：
- 复诊日期：

## 结果分支
- 若支持：
- 若削弱：
- 若无法判断：
```

## 明天开始开发时的优先顺序

1. 复盘问答与原始/整理归档；
2. 事实切片与证据卡；
3. 3—7 天趋势诊断；
4. 微实验与复诊；
5. 项目进度与周计划守卫；
6. 驾驶舱可视化；
7. 外部知识摄入池与定时任务；
8. 月度稳定画像候选。

> 开发原则：先让军师能基于事实形成一个可验证判断，再扩展资料、自动化和复杂界面。
