## 🔴 缺点 1：强依赖 memory 文件体系

**现状**：启动时必须读取 `MEMORY.md`、`user-profile.md`、`feedback-guiding-jerry.md`，任何一个读不到就降级为"通用模式"，丢失所有个人化。

**痛点**：文件路径是硬编码的绝对路径（`C:\Users\jerry\.claude\projects\D--ClaudeData--...`），换电脑、重装系统、目录移动全部炸。

### 优化方案

**① 在 SKILL.md 中增加兜底 profile（15 分钟，改前 20 行）**

在 SKILL.md 的「前置：记忆加载」段落后，直接内嵌一份精简版的默认画像。当外部文件读取失败时，用内嵌版本而不是裸奔。

```markdown
## 内置默认画像（memory 文件不可用时的兜底）

当 memory 文件读取失败时，使用以下内置默认值：

- 默认学习偏好：类比优先，实践驱动，讨厌空话
- 默认薄弱领域：408 四门 + 高数/线代/概率论
- 默认检测节奏：宁严勿宽，答对不表扬，答错直接说
- 默认内耗信号：完美主义、过度自我分析

⚠️ 但这个降级版本不知道你的具体科目进度——建议尽快修复 memory 文件路径。
```

改动量：只在 SKILL.md 里加 10 行。

**② 路径从绝对改为相对（30 分钟，影响较小）**

Claude Code 运行时的工作目录是可预测的。可以把 memory 文件放到 skill 自身目录下，用 skill 的相对路径读取，消除对 `C:\Users\jerry` 的依赖：

```
现在（脆弱）：
C:\Users\jerry\.claude\projects\D--ClaudeData--claude-skills-knowledge-check\memory\MEMORY.md

改为（skill 内自包含）：
{skill目录}/memory/user-profile.md
```

改动量：把三个 memory 文件复制到 knowledge-check/memory/ 下，修改 SKILL.md 的路径引用。但需要维护两处同步。

**投入产出比**：⭐⭐⭐⭐ 极低投入，降级体验从"完全不认识你"到"至少知道你是考研学生、喜欢类比"。

## 🔴 缺点 5：模式零（全局学习框架）容易被跳过

**现状**：用户的第一个指令通常是"检测我"而非"我要学数据结构"。模式零只在新科目出现时触发，触发后还要问三个问题——用户嫌烦直接跳过。

**痛点**：跳过模式零 → 没有全局位置信息 → 导航模式无法做前置依赖分析 → 报告缺少"本章在全局中的位置"——整个系统的纵向坐标丢失。

**不是鸡生蛋——是设计问题**：模式零和检测之间没有强制关联。用户跳过了也不影响检测——所以当然会跳过。

### 优化方案

**① 在检测开头轻量追问前置信息（10 分钟，改模式二的入参）**

不在模式零问三个问题，而是在第一次检测时，把三个问题压缩成一个：

```
当前回答后的追问：
> 检测前确认一件事：这是你学这东西的第几章？目标是考研/自学/期末？手头用什么资料？
```

三个问题一次性抛出来，用户一句话回完。不回也行——不回就降级为"无框架模式"，但至少要问一次。

改动量：在 SKILL.md 的模式二入口加一段条件判断 + 追问。

**② 让模式零"不可跳过"一次（最简单，5 分钟）**

模式零只在第一次提到某科目时弹出一次。弹出后用户必须回答（或不回答并接受降级），但流程不阻塞：

```
你：检测我

系统：检测之前——这是你第一次学「Agent开发」。
     快速确认：
     1. 准备学到什么程度？（如：能独立跑 Workflow）
     2. 手头用什么资料？（如：B站课程 + 笔记）
     3. 有考试/截止日期吗？（无就跳过）

     不回也没关系——检测照样进行，只是后续无法做导航。
```

改动量：在 SKILL.md 的模式调度部分加上"首次科目检测 → 追问三问 → 不回答不阻塞"的逻辑。

**投入产出比**：⭐⭐⭐⭐⭐ 极低投入，填补了系统最大的结构性缺口。

## 🔴 缺点 9：微检测评分精度太粗

**现状**：三档评分映射——✅=0.85、⚠️=0.55、❌=0.2。之间分别是 0.3 和 0.35 的断档。

**痛点**：概念从 0.2 → 0.55 → 0.85 的跳跃太大了。如果你卡在 0.55-0.85 之间，三次微检测可能都是 0.55（因为回答不够 0.85 的标准），看起来像"毫无进步"，但实际上只是评分不够细。

### 优化方案

**五档替换三档（5 分钟，只改 SKILL.md 微检测部分）**

在 SKILL.md 中搜索 `✅=0.85, ⚠️=0.55, ❌=0.2`，替换为：

```markdown
5. **写入知识库**：score 按判定映射为五档：

| 判定 | score | 标准 |
|------|-------|------|
| ✅ 脱口而出 | 0.90 | 不假思索，能用自己的话说清本质 + 能举例 + 能说边界 |
| ✅ 能说清 | 0.75 | 能说清但需要想一想，或例子需要我追问后才给出来 |
| ⚠️ 方向对 | 0.50 | 大体理解方向，但有模糊或细节遗漏 |
| ⚠️ 关键点混淆 | 0.35 | 能说出些东西但核心关系搞反了 |
| ❌ 完全不会 | 0.15 | 无法给出有意义回答 |
```

同时更新知识库的 score 字段含义。

改动量：替换一段映射表，5 分钟。

**额外收益**：五档数据会让总热力图（模式五）的颜色梯度和趋势线更有信息量——三档只有三种颜色，五档可以形成从红到绿的真实渐变。

**投入产出比**：⭐⭐⭐⭐⭐ 改 5 行，追踪粒度翻倍。

## 🔴 缺点 10：没有"检测前回顾上次薄弱点"

**现状**：每次检测是独立的。上次检测显示 score 0.35 的知识点，这次检测时不会主动提起。

**痛点**：这是"知识库有数据但检测流程没利用"的典型。都存了 JSON 了，出题时却视而不见。

### 优化方案

**在模式二第二步（出题）前插入回顾检查（15 分钟，改 SKILL.md）**

```markdown
### 第零步（新增）：回顾上次薄弱点

在开始出题前，检查 knowledge-base/{当前科目}.json：
- 如果当前章节之前检测过，且存在 score < 0.5 的知识点
- 则第一条问题设为回顾题：

> 🔍 **Q0** `[回顾]`：上次检测你在「{知识点}」上卡住了。
> 让我先确认一下你现在补上了没有——{一道针对该知识点的精简问题}

- 答对了：记录 score 提升（如 0.35→0.60），标注"已回补"
- 答错了：不降级追问（避免在回顾上卡太久），直接记录"补了但没补上"，然后进入正式检测

Q0 不计入 5-8 题的上限。
```

改动量：在 SKILL.md 模式二流程总览中插入"第零步"，增加约 30 行。

**投入产出比**：⭐⭐⭐⭐ ⭐ 改了之后，每次检测都是一次"补漏验证"，知识库从死数据变成活数据。

## 🟡 缺点 2：知识库 JSON 结构扁平

**现状**：`科目 → 章节 → detection → knowledge_points`。概念之间没有关系边。

**痛点**：你学了 Hook 又在另一处学了 Git Hook——它们本质是同一个概念的不同应用场景。当前结构无法表达这种"概念 X 出现在科目 A 的第三章和科目 B 的第五章"的跨章节关系。

### 优化方案

**增加 concepts.json 概念级索引（30 分钟，新增文件 + 改 report-agent）**

在 knowledge-base/ 新增一个 `concepts.json`：

```json
{
  "concepts": [
    {
      "id": "hook",
      "name": "Hook（钩子机制）",
      "aliases": ["钩子", "Hook", "事件钩子"],
      "appearances": [
        {"subject": "Agent开发", "chapter": "Hook（钩子机制）", "score": 0.85},
        {"subject": "工程化控制", "chapter": "Git基础", "score": null}
      ],
      "related": ["pipeline", "subagent", "event-driven"],
      "mastery_trend": [0.2, 0.55, 0.85]
    }
  ]
}
```

改动流程：

1. report-agent 写完科目 JSON 后，额外检查本次检测的知识点中是否有之前在其他科目出现过的概念（通过 name/aliases 匹配）
2. 如果有 → 在 concepts.json 中追加 appearance 记录
3. 模式五（总览）增加一个维度：不仅按章节看，还能按"跨科目概念网络"看

改动量：新建 concepts.json，改 report-agent.md（加约 40 行逻辑），改 SKILL.md 模式五（加一个"按概念看"的选项）。

**投入产出比**：⭐⭐⭐ 工作量中等，但对你的 vibecoding 学习特别有用——Agent 开发的很多概念会跨章节反复出现。

## 🟡 缺点 3：HTML 热力图是字符串替换

**现状**：report-agent 用模板占位符（`__CHAPTER_NAME__` 等）做字符串替换生成 HTML。

**痛点**：如果知识点的 evidence/suggestion 中包含 HTML 特殊字符（`<>&"`），没转义就写入 HTML 会让页面崩掉。或者模板路径写错了，静默失败。

### 优化方案

**在 report-agent 中增加 HTML 转义步骤（10 分钟）**

在 report-agent.md 的"第二步：生成 HTML 热力图"中，所有替换到 HTML 的用户内容（evidence、suggestion、章节名）加上一条规则：

```markdown
**HTML 安全规则**：所有替换到 HTML 中的用户文本内容，
在写入前必须对以下字符做转义：
  `&` → `&amp;`
  `<` → `&lt;`
  `>` → `&gt;`
  `"` → `&quot;`

特别是 __DETAILS_JSON__ 中的 evidence 和 suggestion 字段
（它们来自用户的回答总结，可能包含任意字符）。
```

**额外的防御**：在 report-agent.md 第五步返回摘要中增加一个字段：

```markdown
- 热力图验证：{通过/失败——检查 {html_path} 是否存在且大于 0 字节}
```

改动量：加两条规则，不涉及代码。

**投入产出比**：⭐⭐⭐ 改了不一定会好（因为出问题的概率本身不高），但改了绝对不会坏。

## 🟡 缺点 6：expert-agent 科目覆盖有限

**现状**：只有 10 个预定义学科 persona。Agent开发、vibecoding、Claude Code 等不在列表中，降级为"通识学习方法专家"——框架质量打折扣。

**痛点**：这是你**最主要的当前学习方向**。你的核心科目没有被正经覆盖。

### 优化方案

**为你的常用科目新增 expert persona（20 分钟，改 expert-agent.md）**

在 expert-agent.md 的「学科识别与专家切换」表格中，新增几行：

```markdown
| 科目关键词 | 专家身份 | 出题侧重 |
|-----------|---------|---------|
| Agent/Subagent/Hook/Workflow/Claude Code | Agent开发工程师 | 概念本质 + 职责区分 + 实战场景 |
| vibecoding | Vibe Coding 实践者 | 工具链理解 + 工程化流程 + 踩坑经验 |
```

同时在学科识别逻辑中，为这些新科目定义专门的出题策略：

```markdown
#### Agent开发/vibecoding 类

核心任务：**区分"看懂了教程"和"能自己跑起来"**。

出题策略：
- 先问概念的本质区别（如 Hook vs Subagent 的根本差异）
- 再给场景判断题（"你要实现 X 功能，应该用 Hook 还是 pipeline？为什么？"）
- 追问配置细节（"如果 Windows 下 Hook 不触发，你可能忽略了什么？"）
```

改动量：在 expert-agent.md 加约 20 行。

**投入产出比**：⭐⭐⭐⭐ 对你个人使用来说，这是收益最高的改动——你的核心科目终于有了正经的专家 persona。

## 🟡 缺点 7：后台子代理失败没有用户感知

**现状**：report-agent 在后台跑。如果失败，用户不知道——对话里一切正常，但 reports/ 目录是空的。

**痛点**：你以为报告生成了，关掉对话后才发现没有。数据没了。

### 优化方案

**在 SKILL.md 模式三增加一条"完成后确认"规则（5 分钟）**

```markdown
### 子代理完成后的确认

report-agent 后台任务完成后：
- 如果返回摘要中包含 html_path → "报告已生成：{路径}"
- 如果子代理超时/失败/返回异常 → 
  "⚠️ 报告生成子代理未正常完成。已保存本次检测的原始数据，
   重新说「生成报告」可以重试。不会丢失刚才的检测结果。"
```

同时，在 report-agent 返回失败时不静默——让调用方（SKILL.md）感知到失败并告诉用户。

改动量：在 SKILL.md 加约 10 行错误处理。

**投入产出比**：⭐⭐⭐ 修复一个"失败没通知"的静默 bug。

## 🟢 缺点 4：没有 Spaced Repetition 机制

**痛点**：检测过的知识没有自动回顾提醒。知识库里 score 0.35 的知识点放了两周无人问津。

### 优化方案

**① 轻量版：每次开检测时扫描过期概念（20 分钟）**

在每次进入模式二时，在 knowledge-base 中扫描：

```
找出所有 score < 0.5 且距上次检测超过 7 天的知识点。
如果 ≤ 3 个 → 直接提示"这几个概念该回顾了：..."
如果 > 3 个 → 取 score 最低的 3 个提示
```

不改任何文件结构，只加一段扫描和提示逻辑。

**② 完整版：生成复习日历（工作量较大）**

基于 SM-2（SuperMemo 的简化版）为每个知识点计算下次复习时间。但这是个大工程，不推荐现在做。

**投入产出比**：⭐⭐ 轻量版可以做。完整版不值得——对你当前的阶段来说，主动回顾比自动提醒更适合学习节奏。

## 🟢 缺点 8：全文本交互

**痛点**：数学公式只能打字，不能手写拍照。

### 优化方案

**短期不优化。** 这不是 skill 能解决的问题——是 Claude Code 不支持多模态输入。等 Anthropic 开放多模态后再考虑。当前的替代方案是描述"我卡在哪一步"，系统可以用文字出题。

**投入产出比**：⭐ 在平台支持之前，不值得花时间。

---

## 🟢 缺点 11：出题质量依赖 expert-agent 能力上限

**痛点**：如果 expert-agent 对某个领域不熟，出的题不够痛。用户无法区分"答对是因为真懂了"还是"题太简单"。

### 优化方案

**在检测报告里增加"题质量自评"（10 分钟）**

在模式三的口头总结中增加一个可选步骤：

```markdown
问用户：
> 这轮检测的题目——你觉得有戳到你的知识盲区吗？
> 还是说答出来的都是你本来就会的？
```

如果用户反馈"题太简单" → 在 knowledge-base 里标记该章节的检测质量 flag → 下次检测时提醒 expert-agent"用户上次反馈题不够痛，请增加难度和变式"。

改动量：在 SKILL.md 加约 5 行追问逻辑。

**投入产出比**：⭐⭐⭐ 一句话就能收集反馈，用来校准后续出题的难度。
