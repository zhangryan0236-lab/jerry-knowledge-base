# 多学科学习仓库配置

> 配套 [[raw/学习系统说明书/学习仓库搭建指南.md]]。骨架相同，内脏按学科换。
> 核心原则：**文件夹名必须反映你在这个学科里实际在干什么**。

---

## 一、五种学科的底层差异

在动手搭文件夹之前，先搞清楚这五类学科的知识形态有什么区别：

| 学科 | 知识形态 | 学习的核心动作 | 检测的核心动作 |
|------|---------|--------------|--------------|
| **数学**（高数/线代/概率） | 定理 → 公式 → 题型 | 算题、总结题型、整理错题 | 能不能独立解变式题 |
| **408 理论**（计组/计网/OS） | 概念 → 原理 → 流程 | 画图、背流程、理解机制 | 能不能解释每一步的"为什么" |
| **408 实践**（数据结构） | 概念 → 算法 → 代码 | 写代码、分析复杂度、画图 | 能不能手写代码 + 算复杂度 |
| **英语** | 单词 → 语法 → 语感 | 背单词、精读、听力、写作 | 能不能读懂、听懂、写对 |
| **Vibecoding/工具** | 概念 → 配置 → 实操 | 看教程、配环境、动手跑 | 能不能自己配出来、解释为什么 |

**结论**：`概念/` 文件夹对数学意义不大（数学的核心单位是题型，不是概念）。`实战/` 对英语叫什么"实战"？不如叫 `作文/`。文件夹名字关系到你每次打开它时能不能第一时间定位——名字必须和你的学习动作对应。

## 二、各学科适配方案

### 2.1 数学（高数 / 线代 / 概率论）

```
{数学科目}/                        ← 如"高等数学"、"线性代数"
├── README.md                     ← 不变：仪表盘
├── 笔记/                         ← 课堂笔记 + 定理推导（你的手写理解）
│   ├── 03-微分中值定理.md
│   └── 04-不定积分.md
├── 题型/                         ← ⭐ 替代「概念/」——数学的核心单位是题型
│   ├── 罗尔定理-证明题.md         ← 一个题型一个文件：常见考法 + 解题模板 + 陷阱
│   ├── 拉格朗日-应用题.md
│   └── 不定积分-换元法.md
├── 错题/                         ← ⭐ 数学特有——错题本是数学的生命线
│   ├── 错题-微分中值定理.md       ← 按章节分，每道错题：原题 + 错因 + 正确解法 + 同类题
│   └── 错题总览.md               ← Dataview 汇总所有错题
├── 检测报告/                     ← knowledge-check 生成（数学类走变式题策略）
│   ├── 检测报告-微分中值定理-{日期}.md
│   └── 检测报告总览.md
├── 框架/                         ← expert-agent 梳理的定理依赖图
│   └── 框架-微分中值定理.md       ← 重点：罗尔→拉格朗日→柯西的推导链
├── 公式卡/                       ← ⭐ 数学特有——一个公式一个卡片
│   └── 积分公式速查.md
├── 思维导图/
│   └── 中值定理-推导链.png
├── 原始资料/
│   └── 课程大纲.md
└── 习题/                         ← ⭐ 替代「实战/」——分批做的练习题
    ├── 基础题/
    └── 强化题/
```

**为什么这样改**：

| 原来（通用） | 数学版 | 原因 |
|-------------|--------|------|
| `概念/` | `题型/` | 数学不按"概念"组织——你考试的时候面对的是"一道证明题"而不是"拉格朗日这个概念" |
| 无 | `错题/` | 数学的进步就靠错题。没有错题本的数学学习是假的 |
| `实战/` | `习题/` | 数学的"实战"就是做题 |
| 无 | `公式卡/` | 考前 10 分钟翻的不是笔记，是公式卡 |

### 2.2 英语

```
英语/
├── README.md                     ← 仪表盘：各模块掌握率
├── 单词/                         ← ⭐ 替代「概念/」——英语的核心单位是单词
│   ├── 雅思核心-List01.md
│   ├── 雅思核心-List02.md
│   └── 生词本.md                 ← 阅读/听力中遇到的生词汇总
├── 语法/                         ← ⭐ 英语特有
│   ├── 从句.md
│   └── 时态.md
├── 阅读/
│   ├── 精读-{文章标题}.md         ← 逐句分析 + 生词 + 长难句拆解
│   └── 泛读记录.md
├── 听力/
│   ├── 精听-{材料}.md             ← 点听+精听训练记录（你自创的那套方法）
│   └── 泛听记录.md
├── 写作/
│   ├── 作文-{题目}.md
│   └── 模板与句型.md
├── 口语/
│   └── 话题卡-{主题}.md
├── 检测报告/                     ← knowledge-check（英语可能用得少，见下文）
│   └── 检测报告总览.md
├── 原始资料/
│   ├── 课程大纲.md
│   └── 真题链接.md
└── 错题/                         ← 阅读/听力的错题分析
    └── 错题总览.md
```

**英语的特殊性**：

- **knowledge-check 在英语上用处有限**。目前的 skill 没有英语检测 persona（expert-agent 里没有雅思/英语类）。阅读和听力更适合用"自测 + 错题记录"的方式，真正需要 AI 检测的主要是**单词掌握度**和**语法理解**。
- **框架/ 基本用不上**。英语没有定理依赖图。如果一定要有，语法之间的依赖关系可以画一个简单的。
- **英语的"概念"是语法的规则**，放 `语法/` 里。
- **你已经有一套听力训练方法（点听+精听）**——`听力/` 文件夹直接为这套方法服务。

### 2.3 408 计算机统考

408 有四门课，有两种组织方式：

#### 方案 A：一门课一个文件夹（推荐）

```
数据结构/                          ← 独立科目文件夹
├── README.md
├── 笔记/
├── 概念/                          ← 408 的概念性很强，保留
│   ├── 时间复杂度.md
│   ├── 链表.md
│   └── 二叉树.md
├── 算法/                          ← ⭐ 408 特有——手写代码的核心
│   ├── 排序-快排.md
│   ├── 查找-二分.md
│   └── 树-遍历.md
├── 代码/                          ← ⭐ 实际跑代码（区别于手写算法）
│   └── {题目}/
├── 检测报告/
├── 框架/
├── 思维导图/
├── 错题/
└── 原始资料/

计组/                              ← 同上结构
计网/
OS/
```

#### 方案 B：408 总文件夹 + 四门子文件夹

```
408-计算机统考/
├── README.md                       ← 408 全局仪表盘（四门课进度一览）
├── 数据结构/                       ← 子文件夹，结构同方案 A
├── 计组/
├── 计网/
└── OS/
```

**我推荐方案 A**。408 四门课内容差异大，各自有独立的检测节奏，放在一起反而容易互相拖累。

**408 与数学的关键区别**：

| | 408 | 数学 |
|--|-----|------|
| 核心单位 | 概念 + 算法 + 流程 | 定理 + 题型 |
| `概念/` | ✅ 非常重要（如"虚拟内存""死锁"） | ❌ 换成 `题型/` |
| `错题/` | ✅ 有，但重要性不如数学 | ✅ 生命线 |
| 新增 | `算法/`（手写代码）、`代码/`（跑代码） | `公式卡/` |

## 三、各学科 knowledge-check 使用策略

不同学科用 knowledge-check 的方式不同：

| 学科 | 用的模式 | 频率 | 注意事项 |
|------|---------|------|---------|
| **数学** | 完整检测（模式二，数学策略） | 每章一次 | 不会给选择题，核心是变式题 + 追问前提条件。**不做微检测**——数学不适合 2 题定结果 |
| **408 理论**（计组/计网/OS） | 完整检测 + 微检测 | 每章一次 + 模糊概念随时测 | 概念类策略，递进问本质→关联→边界→应用 |
| **408 实践**（数据结构） | 完整检测（数学策略） | 每章一次 | 算法题走数学策略（不给选择题，追问每步的"为什么"） |
| **英语** | 暂不适用 | — | skill 没有英语 persona，建议用错题自测代替。如果后续加了英语 persona 再启用 |
| **Vibecoding/工具** | 微检测为主 | 每个概念一次 | 概念粒度小，2-4 题够用。完整检测仅用于大章节（如"Agent开发全流程"） |

## 五、跨学科 wiki 怎么接

不同学科产出的概念，在 wiki 里的落点不同：

| 学科 | 晋升到 wiki 什么位置 | 例子 |
|------|---------------------|------|
| 数学 | `wiki/概念/`（如果概念足够通用，如"极限的思维方式"） | 大多数数学概念不会晋升 wiki——数学太专了 |
| 408 | `wiki/概念/`（跨学科概念如"缓存""并发"） | `wiki/概念/缓存.md` 连接计组 Cache + OS 页面置换 + 计网 CDN |
| 英语 | `wiki/概念/`（学习方法论，如"点听+精听法"） | `wiki/学习系统/英语听力训练法.md` |
| Vibecoding | `wiki/AI学习/` 或 `wiki/概念/` | `wiki/AI学习/Hook.md` |

**判断标准**：这个概念能不能在我学另一门课时再次出现？能 → 晋升 wiki。不能 → 留在科目文件夹。

## 六、一个建议：先跑通一个，再复制

你现在同时在学的东西很多。建议：

```
优先搭好 → Agent开发/（你已经在学了，最熟）
         ↓ 跑通完整流程：学→检测→晋升 wiki
         ↓
然后搭 → 数据结构/（408 第一门，概念 + 代码双轨）
         ↓
再搭 → 高数/（数学特有：题型 + 错题本）
         ↓
最后 → 英语/（knowledge-check 暂不适用，以自测为主）
```

**不要把四个科目一起搭**——你会花一整天在建文件夹、写 README、调结构上，真正学习的时间为零。先跑通一个，确认这套流程对你有用，再逐个复制。
