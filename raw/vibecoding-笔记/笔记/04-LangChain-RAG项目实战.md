## 一、RAG 基础概念

**RAG = Retrieval Augmented Generation（检索增强生成）**

模型能回答互联网公开知识，但无法回答**私有知识**（如企业内部文档、学校职工名单等）。RAG 的核心思路是：**给模型外挂知识库**，让模型在回答问题前先检索相关文档片段，再基于这些参考信息生成答案。

**两条主线：**

| 流程 | 做什么 | 目的 |
|------|--------|------|
| **离线处理** | 上传文档 → 提取文本 → 切片分块 → 向量嵌入 → 存入向量库 | 为知识库建立索引，方便语义检索 |
| **在线处理** | 用户提问 → 向量化 → 向量库相似匹配 → 取回相关片段 → 组装 Prompt → 模型生成回答 | 让模型基于检索到的参考信息回答问题 |

核心链路：**文档 → 分段 → 向量化 → 存向量库**（离线）；**问题 → 向量化 → 语义匹配 → 取回段落 → 喂给 LLM**（在线）

## 二、项目概述

### 项目定位
基于 **LangChain 框架** 构建的**企业级 RAG 知识库问答系统**，面向电商平台（服装类商品）的智能问答场景。

### 场景假设
- 我是一个**在校大学生**，技术基础薄弱
- 毕设题目：用 LangChain 做 RAG 项目
- 使用 **Vibe Coding（氛围编程）** 方式，让 AI 辅助完成
- 先跟 AI 用 Plan 模式沟通方案，达成一致后再生成代码

## 三、技术栈

### 方案讨论过程

| 阶段 | 方案 | 最终决定 |
|------|------|---------|
| **LLM** | 最初：Ollama + Qwen2.5 7B（本地运行） | 改为：**阿里云百炼 API**（DeepSeek V4 系列），避免本地显卡性能不足 |
| **Embedding 模型** | BGE-M3 | 同样走阿里云百炼 API |
| **后端框架** | FastAPI（Python 3.11） | ✅ 保留 |
| **前端框架** | React 18 + TypeScript | ✅ 保留 |
| **UI 组件库** | Ant Design 5 | ✅ 保留 |
| **向量数据库** | ChromaDB | ✅ 保留 |
| **关系型数据库** | SQLite（SQLAlchemy ORM） | ✅ 保留 |
| **部署方式** | 最初：Docker Compose | 改为：**start.bat 本地一键启动**（网络原因 Docker 镜像拉取困难） |

### 最终技术栈总览

```
前端层：    React 18 + TypeScript + Ant Design 5
后端层：    FastAPI + LangChain + LangChain Community
数据库：    SQLite（关系）+ ChromaDB（向量）
模型服务：  阿里云百炼 API（大模型 + Embedding）
部署方式：  start.bat 本地启动
```

## 五、功能需求

| 编号 | 功能 | 说明 |
|------|------|------|
| 1 | **知识库管理** | 支持上传、管理商品知识文档；仅管理员可操作 |
| 2 | **知识库问答** | 用户提问时，系统从知识库检索相关内容辅助回答 |
| 3 | **引用显示** | 回答时展示引用了知识库的哪些片段 |
| 4 | **多用户与会话** | 支持多用户注册登录，每个用户拥有独立会话 |
| 5 | **历史对话恢复** | 用户再次登录后可找回历史对话 |
| 6 | **用户管理** | 注册、登录、修改密码；管理员 admin / 123456 |
| 7 | **权限控制** | 仅管理员可管理知识库，普通用户只能问答 |
| 8 | **性能优化** | 流式响应、历史窗口限制、批量向量化、查询缓存、异步 IO、前端防抖等 |
| 9 | **附加功能** | 答案反馈、建议问题、引用高亮、对话导出、暗色模式、知识库健康看板 |

### 核心技术流程

**离线（知识摄入）：**
```
文件上传 → 类型检测 → 文档加载器分发（TXT/PDF/CSV）
    → 内容清洗 → 文本分片 → 元数据丰富（来源/类别/产品名）
    → 去重 → 批量向量化 → 存入 ChromaDB
```

**在线（检索问答）：**
```
用户提问 → 问题预处理 → 向量化 → 余弦相似度搜索
    → 取回相关片段 → 上下文组装 → LLM 生成回答 → 流式返回
```

## 六、Vibe Coding 开发实战流程

### 第 1 步：沟通方案（Plan 模式）

1. 创建项目文件夹 → VS Code 打开 → 启动 Claude Code
2. 选择 **Plan 模式**，输入需求提示词（模仿小白视角）
3. 关键提示词内容：
   - 我要做毕设：LangChain + RAG 企业级知识库问答
   - 技术选型你定，但必须用 LangChain
   - 功能要求：知识库管理、问答、多用户会话、权限控制
   - 需要性能优化（答辩亮点）
4. AI 输出方案：技术栈、架构图、数据模型、API 设计、RAG 管道流程

### 第 2 步：方案调整

与 AI 讨论两个关键调整：
1. **Ollama 本地 → 阿里云 API**：避免电脑配置不够（需独立显卡 8GB+ 显存）
2. **Docker → start.bat**：解决 Docker 镜像拉取困难问题

### 第 3 步：接受方案 → 代码生成

- AI 自动生成完整项目代码（后端 FastAPI + 前端 React）
- 中途提供阿里云百炼 API Key
- AI 自动执行 `npm install` 等依赖安装命令

### 第 4 步：调试与启动

- **第一次启动失败**：start.bat 运行后网页无法访问
- **第二次启动**：中文乱码问题（Windows CMD 编码）
- **最终成功启动**：浏览器访问 localhost:5173，使用 admin/123456 登录

### 第 5 步：验证

第一版成功运行，包含：
- 登录页面
- 会话管理页面
- 知识库管理入口
- 个人中心
- 修改密码功能

## 七、阿里云百炼配置要点

1. 访问 [百炼平台](https://bailian.aliyun.com) → 注册/登录
2. 必须完成**实名认证**才能调用 API
3. 新用户有 **3 个月免费额度**，每个模型约 100 万 Token
4. 创建 API Key：模型 → API-Key → 创建 → 保存好密钥（关闭后不可找回）
5. DeepSeek V4 系列模型在百炼平台可用

## 八、关键经验

- **Vibe Coding 有效的前提**：需求描述要清晰，先讨论方案再写代码
- **Plan 模式的价值**：让 AI 先输出架构设计方案，小白也能理解全局
- **AI 写代码虽快，但 debug 仍然需要人介入**：Windows 编码问题需人工反馈
- **本地模型 vs 云端 API**：云端 API 门槛更低，适合多数人；本地 Ollama 需要独立显卡
- **第一版跑起来 ≠ 项目完成**：后续还需要深度测试、代码评审、单元测试
