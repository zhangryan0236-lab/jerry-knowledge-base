# Hook（钩子机制）

## 一句话定义

Hook 是**事件感应器**——当 X 发生时，自动执行 Y。它不改变 X 和 Y 的内容，只在中间做一个微小的连接。

> 💡 **来自一次理解检测的自我提炼**：Hook 是一个检测到 A 就执行 B 的机制。它只是在 A 和 B 中间充当一个**感应器**，感应到 A 就执行 B，不对 A 和 B 这两块的内容有所改变，只做一个**微小的连接**。

## 核心要点

1. **无状态**——来一条事件处理一条，不记录历史
2. **不参与业务逻辑**——它不改变事件本身的内容
3. **可以拦截**（阻止后续操作）也可以只记录（旁路观察）
4. **自动触发**——不需要手动调用，事件发生就自己跑

## Hook vs Subagent

| | Subagent | Hook |
|--|----------|------|
| 角色 | **执行者**——领任务、干活、返回结果 | **旁观者**——拦截事件、做检查 |
| 是否有状态 | 有——知道自己在执行什么任务 | **无状态**——来一条处理一条 |
| 谁控制 | 主 Agent **主动**派发 | 事件 **自动**触发 |
| 类比 | 临时叫来的电工 | 公司门口的安检闸机 |

## Hook 的四种常见类型

| 种类 | 事件 | 用途 |
|------|------|------|
| Git Hook | `git commit` | 提交前自动跑 lint |
| Webhook | GitHub 收到 Issue | 跨系统自动通知 |
| 框架生命周期 Hook | Vue 组件挂载完成 | 在组件出生/活着/死去时插入代码 |
| Claude Code Hook | PreToolCall | 拦截工具调用做质量检查 |

## 我的理解

> Hook 不负责"等三个 Subagent 都完成然后进入下一步"——那是 pipeline() 的工作。Hook 只是路过时看一眼：有人要执行 git commit？我先拦截检查一下通行证。不管通行证是谁写的、谁发的——它只管检查。
