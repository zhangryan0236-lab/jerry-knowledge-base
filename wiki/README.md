# 知识维基系统

> 基于 Karpathy 的 LLM Wiki 模式，构建由 AI 协助维护的持久化知识库。

## 核心理念

传统用法 RAG（上传文件 → 每次问答重新检索）的问题是：**没有积累**。

这套系统的核心不同：你添加原始资料 → AI 读取、提取关键信息，并将其**整合进一个持续存在的维基**，而不是每次从零重新发现知识。

```
你负责：寻找资料、探索、提出好问题、思考意义
AI 负责：总结、交叉引用、归档、维护一致性、更新索引
```

**Obsidian 是 IDE；AI 是程序员；维基是代码库。**

---

## 三层架构

| 层级 | 说明 | 在你的知识库中对应 |
|------|------|-------------------|
| **原始资料**（Raw Sources） | 不可变的原始文件 — AI 读取但不修改 | `raw/`（含 Clippings/、学习日志、抖音视频等子目录） |
| **维基**（The Wiki） | AI 生成和维护的 Markdown 文件 — 摘要、概念页、实体页、比较 | `wiki/`（含概念、学习系统、自我认知、核心目标、AI学习等子目录） |
| **模式**（The Schema） | 告诉 AI 维基的结构、惯例、工作流程 | `CLAUDE.md` 中的维基指令 + `wiki/.workflow` |

---

## 三个核心操作

### 1. 🍽️ 摄入（Ingest）
> 你放入新资料 → AI 处理并整合进维基

流程：读取资料 → 与你讨论要点 → 写入维基摘要页 → 更新索引 → 更新相关概念/实体页 → 记录日志

### 2. 🔍 查询（Query）
> 你对维基提问 → AI 搜索相关页面 → 综合回答

重要洞察：**好的答案可以归档为维基新页面**。你要求做的比较、分析、发现的联系——这些不应该消失在聊天记录里。

### 3. 🧹 巡检（Lint）
> 定期让 AI 对维基做健康检查

检查：页面间矛盾、过时主张、孤立页面、缺失交叉引用、数据空白。
