# 问题挖掘与学习导航系统

> 这套系统解决的不是“我该看哪本书”，而是先回答：我现在到底遇到了什么问题？

## 核心闭环

```text
模糊不适 → 具体事件 → 事实记录 → 候选问题 → 主要矛盾
→ 解决假设 → 匹配资料 → 微型实验 → 反馈 → 再诊断
```

## 诊断原则

1. 先调查，不从感觉直接下结论。
2. 先找阻断学习闭环的环节，再找宏大解释。
3. 一次只处理一个主要矛盾。
4. 书籍是解决假设，不是权威处方。
5. 任何方案必须进入 1—3 天微实验。
6. 实验失败只推翻假设，不推翻人。

## 主动导航范围

诊断完成后，不只推荐学习资料，也根据问题匹配：

- 知识与教材：补概念、前置和结构；
- 书籍：提供模型和长期理解；
- 播客/访谈：接触真实经验和行业判断；
- 电影/纪录片：拓展处境、价值冲突和审美经验；
- GitHub 工具：降低实践摩擦、制造反馈和自动化重复劳动。

资源推荐不超过三项，且必须说明“它解决什么问题、不能解决什么、看/用完之后做什么”。本地资料优先，其次是官方来源；GitHub 项目必须核验活跃度、平台支持和许可证。

## 主动预警

当每日复盘或对话中连续出现同一信号，系统可以主动提出待诊断问题，不需要 Jerry 先把问题想清楚。主动预警必须说明观察证据、当前假设和不确定性，然后只问一个具体问题。

## 使用入口

调用 `problem-diagnosis-learning` Skill，或直接说：

> 帮我挖掘问题：{具体困惑}

系统默认先追问，不直接给书单；完成问题定位后，再输出匹配资料和微实验。

## 持续交互协议

每日复盘、零散思考、读书感受、电影感受和对未来的看法，都可以作为动态材料。交互不以一次总结结束，而是采用：

```text
认真回应 → 连接已有模式 → 追问一个问题 → 等待回答 → 再深入
```

如果内容只是体验或审美，不强行诊断；如果出现连续行为信号，再主动提出问题假设。每轮最多推进一个问题，直到 Jerry 说暂停或问题已经足够清楚。
