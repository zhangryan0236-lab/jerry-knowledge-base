## 第一部分：总纲

### 1.1 哲学基础：实践论

这套系统的元模型来自毛泽东的 [[raw/毛泽东选集/实践论/论认识和实践的关系|实践论]]，核心就一句话：

```
实践 → 认识 → 再实践 → 再认识 → ⋯
每一次循环都比上一轮进到了高一级的程度。
```

翻译成你的学习系统：

| 实践论 | 你的学习系统 | 具体动作 |
|--------|------------|---------|
| **实践** | 学习行为 | 看课、读书、做题、写代码 |
| **认识（感性→理性）** | 复盘提炼 | 每日3问、周数据、知识检测 |
| **再实践** | 用规律指导下一轮 | "明天第一件事"、周调整 |
| **再认识** | 审视系统本身 | 月度复盘、版本更新 |

**关键推论**：

1. **系统不能从空想中来。** 你不是先设计完美系统再开始学——你是先开始学，在实践中发现问题，再把解决方案写进系统。这本手册的 v1.0 是你当前认知的上限，v1.1 一定来自你跑出来的真实问题。
2. **复盘不是"附加动作"，复盘就是学习本身。** 只实践不复盘 = 经验主义（盲目工作）。只复盘不实践 = 教条主义（空谈）。二者缺一，都不是完整的学习。
3. **"完成"是相对的。** 实践论说："对于这一具体过程的认识运动算是完成了。然而对于过程的推移而言，人们的认识运动是没有完成的。" 你的 408 考完，这套系统的一个具体应用周期就完成了——但学习系统本身没有终点，它在下一个目标中继续进化。

### 1.2 三条铁律

这三条是设计这套系统时不可妥协的原则：

**铁律一：按你最差的那天设计。**

状态好的时候什么系统都能用。但你瘫在床上不想动的时候，这套系统必须还能启动。每个环节都要问自己："如果今天我只剩 10% 的意志力，这一步还做得动吗？" 做不动就简化。

**铁律二：交付物 > 感觉。**

"我觉得学会了"不可靠。可靠的证据链是：笔记数量、正确率趋势、费曼录音、复盘记录。系统里的每一个环节都要产出**可触摸的交付物**——不是给别人看的成绩单，是给你自己的认知脚手架。详见 [[wiki/学习系统/交付物的深层理解|交付物的深层理解]]。

**铁律三：一次只改一个东西。**

每月复盘后你可能会发现 5 个想改的地方。忍住。只改 1 个，跑一个月，看效果，再决定下一个。如果你一次改 5 个，你就不知道哪个改对了、哪个改错了。

### 1.3 系统全景图

```
┌─────────────────────────────────────────────────────────┐
│                    学习系统全景                           │
│                                                         │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐           │
│  │  输入端   │ →  │  处理端   │ →  │  输出端   │           │
│  │          │    │          │    │          │           │
│  │ 教材/课程 │    │ 学→笔记   │    │ 笔记卡片  │           │
│  │ 书籍     │    │  →做题    │    │ 费曼录音  │           │
│  │ 播客/视频 │    │  →讲出来  │    │ 复盘记录  │           │
│  │ 文章/剪藏 │    │          │    │ 周数据表  │           │
│  └──────────┘    └──────────┘    └──────────┘           │
│                         ↓                               │
│              ┌──────────────────────┐                   │
│              │      复盘层           │                   │
│              │                      │                   │
│              │  每日3问 → 每周数据   │                   │
│              │  → 月度系统审视       │                   │
│              └──────────────────────┘                   │
│                         ↓                               │
│              ┌──────────────────────┐                   │
│              │    防崩溃机制         │                   │
│              │  接上昨天的自己        │                   │
│              └──────────────────────┘                   │
│                                                         │
│  外围循环：实践 → 认识 → 再实践 → 再认识 → 版本更新       │
└─────────────────────────────────────────────────────────┘
```

整个系统只有**四条管道**，缺一条就会漏：

1. **输入→处理→输出**：这是每天跑的主管道。断在这里 = 今天没学。
2. **复盘**：把输出变成认知。断在这里 = 学了但没沉淀。
3. **防崩溃**：管道断了怎么接上。没有这个 = 断一天变断一周。
4. **迭代**：系统本身怎么升级。没有这个 = 两个月后用着过时的系统。

## 第二部分：日常操作层

> 这是你每天要跑的东西。每个环节都有具体的操作步骤。

### 2.1 输入端：怎么摄入知识

#### 知识来源分类

把你的输入来源分四类，每类的处理方式不同：

| 类型 | 来源举例 | 特点 | 处理方式 |
|------|---------|------|---------|
| **A类：系统课程** | 王道408、网课、教材 | 结构化、有章节、需要深度掌握 | 用 50 分钟闭环（见 2.2） |
| **B类：整本书** | 《学习之道》《纳瓦尔宝典》 | 长篇、有体系、需要提炼 | 读一章 → 写一页概念笔记 → 关联已有知识 |
| **C类：碎片输入** | 抖音、B站、播客、文章 | 零散、质量不一、快速消费 | 有价值的内容 → 即时记一句话 + 标签 → 周末集中处理 |
| **D类：实践学习** | 写代码、搭工具、做项目 | 边做边学、问题驱动 | 遇到问题 → 解决 → 记录"问题-原因-解法"三元组 |

#### A类摄入标准流程（408 备考专用）

```
1. 打开王道/课本对应章节
2. 看一遍（30-40min）
3. 用自己的话写笔记（模板见 2.3）
4. 做对应真题/习题
5. 标记对错，错题记录错误原因
6. 关书讲一遍（录音或自言自语）
```

**判断标准**：讲得出来 = 会了。讲不出来 = 回去再看。

#### B类摄入标准流程（书籍）

```
1. 读一章（不记笔记，专注读）
2. 合上书，回忆 3 个核心观点
3. 每个观点写一段自己的理解（不是摘抄）
4. 标注：这个观点能用到我的哪个场景？
```

#### C类摄入标准流程（碎片信息）

```
1. 看到有价值的内容 → 立刻记一句话（不要等）
   格式：【来源】核心观点（一句话）
   例如：【抖音-某博主】组块化学习的关键是先拆后连
2. 周末花 30 分钟集中处理本周碎片
   - 值得深挖的 → 升级为 B 类处理
   - 只是有趣但无关联的 → 保留但不深挖
   - 看了就忘的 → 直接删
```

**关键原则**：碎片输入最容易造成"我在学习"的幻觉。C 类不做深度处理的话，95% 会在 48 小时内遗忘。周末集中处理就是防止这个。

#### 理解检测

当你觉得"学会了"的时候，用以下四种方式检测（任选其一即可）：

| 检测方式 | 操作 | 检测什么 |
|---------|------|---------|
| **苏格拉底追问** | 问自己"为什么"直到答不出来 | 理解的深度 |
| **费曼检测** | 用给初中生讲课的方式解释 | 是否真懂（而非背概念） |
| **迁移测试** | 用一个不相关的领域来解释这个知识 | 是否抓住了本质结构 |
| **反向论证** | 扮演反对者攻击这个知识 | 是否看到了边界和局限 |

**检测结果判定**：

- 卡在"复述"层 → 你只是记住了文字，不理解
- 卡在"解释"层 → 你理解了，但不能迁移
- 卡在"迁移"层 → 你理解了本质，但还不能批判
- 通过"批判"层 → 这个知识点真正属于你了

> 详细说明见 [[wiki/学习系统/如何进行正确的输入]]

### 2.2 处理端：50分钟闭环

这是你学习系统的**最小可运行单元**。每天至少跑 1 个闭环（状态好跑 3-4 个）。

```
一个完整的 50 分钟闭环：

学一个知识点（看王道/课本/视频）    15 min
  ↓
用自己的话写笔记                   15 min
  ↓
做对应题目                        20 min
  ↓
错的标记错误原因                    5 min
  ↓
关书讲一遍（录音）                 10 min
```

**每一个闭环产出 4 样东西**：

1. **1 张笔记卡片** — 见 2.3 模板
2. **1 个正确率数据** — 填进周数据表
3. **1 次提取练习** — 做题 + 讲出来 = 测试效应
4. **1 次元认知校准** — 你觉得会了 vs 你实际做对了 = 差距

**408 备考的闭环节奏建议**：

- 上午：2 个闭环（数据结构 or 计组）
- 下午：2 个闭环（操作系统 or 计网 + 数学）
- 晚上：1 个闭环 + 每日复盘

**通用学习（非 408）的闭环变体**：

```
输入（读/看/听）             20 min
  ↓
笔记（自己的话）             10 min
  ↓
关联（和已有知识连线）        10 min
  ↓
输出（写一段总结/讲出来）     10 min
```

产出：1 张概念笔记 + 1 个交叉引用 + 1 次提取

### 2.3 输出端：笔记与交付物

#### 笔记卡片模板

**408 知识点卡片**：

```markdown
---
tags: [408, 数据结构/计组/OS/计网]
---

# [知识点名称]

- **一句话定义**：
- **一道真题/例题**：
- **和哪个知识点关联**：[[xxx]]
- **我错过的点**：
```

**通用概念卡片**：

```markdown
---
tags: [相关标签]
created: YYYY-MM-DD
---

# [概念名称]

- **一句话定义**：
- **核心要点**（3-5 条）：
- **关联知识**：[[xxx]]
- **来源**：[[原始资料]]
```

#### 交付物检查清单

每周结束时确认以下交付物存在：

| 交付物 | 存储位置 | 频率 |
|--------|---------|------|
| 408 笔记卡片 | `notes/408/` 或对应文件夹 | 每天 |
| 每日复盘记录 | 每日笔记 | 每天 |
| 费曼录音/文字 | 每日笔记 | 每闭环 |
| 周数据表 | `wiki/学习系统/周数据/` | 每周 |
| 周复盘记录 | 同上 | 每周 |
| 月度系统复盘 | 本手册版本记录 | 每月 |

### 2.4 每日复盘

**时间**：睡前 5 分钟。不要超过 5 分钟。

**回答 3 个问题**，一个字都不要多写：

```
- 今天学的最重要的一个东西是什么？（一句话）
- 哪里卡住了？（一个具体知识点，用 [[]] 链到对应笔记）
- 明天第一件事做什么？（一个具体动作，如"刷完王道3.2的15道题"）
```

三个问题分别对应：

| 问题 | 作用 |
|------|------|
| 最重要 | **巩固**：提取今天最重要的内容（测试效应） |
| 卡住了 | **暴露盲区**：诚实面对不会的（元认知校准） |
| 明天第一件事 | **降低决策成本**：明天不用想该干啥，直接做 |

**注意**："明天第一件事"是这套系统最重要的单行文字。它让你第二天不需要做任何决策——决策疲劳是所有崩溃的第一推手。

## 第三部分：周期复盘层

> 每日复盘是接续自己。周期复盘是看清趋势。

### 3.1 每周复盘

**时间**：每周六下午，15 分钟。不要超过 15 分钟。

**第一步：填数据**

| 周 | 新增笔记 | 做题量 | 正确率 | 最大盲区 | 下周 1 个调整 |
|----|---------|--------|--------|---------|-------------|
| 1  |         |        |        |         |             |

- **新增笔记**：本周写了几张卡片
- **做题量**：做了多少道题
- **正确率**：对的 / 总的
- **最大盲区**：从每日复盘的"卡住了"中，找出出现最多次的那个

**第二步：回答 3 个问题**

```
1. 本周最大的盲区是什么？（从每日"卡住了"中找模式）
2. 哪个方法本周有效？哪个没效果？
3. 下周只改 1 件事——是什么？
```

**第三步：把"下周只改 1 件事"写进下周一复盘的"明天第一件事"里。**

**为什么只改 1 件事？** 因为你在做一个对照实验。如果改 3 个，下周数据变好了，你不知道是哪个改对了。改 1 个，数据变化就是它的功劳。

### 3.2 月度系统复盘

**时间**：每月最后一天，30 分钟。

> ⚠️ 这一层复盘的对象**不是你的学习内容**，而是**你的学习系统本身**。

**回答 5 个问题**：

```
1. 这个月实际做到的事 vs 月初计划的事，差距在哪？
   
2. 系统里哪个环节最常断掉？
   （选项：启动不了 / 做一半走神 / 复盘没写 / 数据没填 / 笔记写了但没复习）
   
3. 我是在用"系统"还是在用"感觉"？
   证据检查：
   - 这周的周数据表填了吗？（是/否）
   - 每日3问连续做了吗？（连续天数：__）
   - 50分钟闭环跑了几次？（__/计划）
   如果三个都否：你这个月在用感觉，不是用系统。
   
4. 有没有一个东西是"设计时觉得有用，但一次都没用过"的？
   → 在下个版本里删掉它。
   
5. 有没有一个东西是"每次都在喊缺，但一直没加"的？
   → 在下个版本里加一个最小的版本，现在就可以写的。
```

**做完后必须做的动作**：

1. 更新本手册的版本号（v1.0 → v1.1）
2. 在 5.3 版本记录里写一行改动说明
3. 把改动的部分在手册正文里对应位置更新

**为什么月度复盘如此重要？** 这是实践论说的"再认识"——你跳出日常学习，站在系统外面审视它。没有这一层，你的系统就是静止的，不会进化。

## 第四部分：防崩溃机制

> 这一层专门应对你的 [[wiki/概念/内耗回路|内耗回路]] 和 [[wiki/概念/鸡血驱动与习惯系统|鸡血递减]]。

### 4.1 崩溃信号识别

出现以下任一信号，触发防崩溃机制：

| 信号 | 表现 |
|------|------|
| **连续 2 天没跑闭环** | 不是"太忙"，是系统已经断了 |
| **打开 Obsidian 不知道该干什么** | 决策疲劳，昨天没写"明天第一件事" |
| **开始想"我这个系统是不是有问题"** | 元认知在逃避行动，用"分析系统"代替"开始学习" |
| **刷手机/刷视频超过 30 分钟停不下来** | 多巴胺低点，系统启动失败 |
| **感觉"学不进去""脑子是空的"** | 认知资源耗尽或情绪过载 |

**关键**：任何一个信号出现，立即执行 4.2，不要继续分析自己为什么崩溃。分析自己就是逃避行动。

### 4.2 最小可运行单元

当你处于崩溃状态时，**放弃所有"应该"**。你今天只做一件事：

```
1. 打开 Obsidian
2. 找到昨天（或最近一次）的每日复盘
3. 看最后一行："明天第一件事做什么"
4. 做那件事。就那一件。
5. 做完后在今天的复盘里写："完成了。接上了昨天的自己。"
6. 今天就算成功。
```

**为什么这个能工作**：

- **零决策**：你不用想"今天干什么"，昨天的你已经替你决定了
- **启动成本极低**：一件事，不是"学一整天"，不是"跑 4 个闭环"
- **连续感是心理韧性**：你看到昨天的自己→今天的自己接上了，这本身就是动力
- **扩展心智**：你的笔记在替你记住"你是谁、你在干什么"，不需要用大脑来维持身份认同

**如果你连昨天的那一件都做不动**：

降级到"最小原子动作"——打开 Obsidian，写一句话：

```
今天的复盘：
- 今天学的最重要的：无
- 卡住了：启动失败
- 明天第一件事：[随便写一个，哪怕是"打开王道第3章第2节，看第一页"]
```

只要你写了这一行，你就接上了。今天不算空白。

### 4.3 接续协议

崩溃之后恢复的第一天，你需要一个过渡日：

```
过渡日协议：
1. 不做新东西。只复习昨天的内容。
2. 跑 1 个闭环（不是 3-4 个）
3. 复盘里写"完成了。接上了昨天的自己。"
4. 第二天恢复常规节奏
```

**不要做的事**：崩溃两天后试图"加倍补回来"。崩溃→补课→累→再崩溃，这是最常见的恶性循环。过去的已经过去了，你只能接上今天。

## 第五部分：系统迭代机制

### 5.1 修改原则

这本手册是你的交付物，也是你的活文档。修改它需要遵守以下原则：

```
1. 一次只改一个东西（铁律三）

2. 每次改动必须有来源
   - 来自月度复盘发现的问题 → 改
   - 来自连续两周复盘中提到的同一痛点 → 改
   - 来自"我觉得应该加一个..." → 不改。需要有数据/证据。

3. 每次改动必须更新版本号

4. 每次改动必须记录在 5.3 版本记录里
   格式：vX.Y (日期) — 改了什么、为什么改

5. 删东西比加东西更需要勇气
   每加一个环节，问自己："如果今天我只剩 10% 意志力，这个环节还跑得动吗？"
   跑不动就简化，或者延迟到"状态好时可选"。
```

### 5.2 反馈来源

系统迭代的输入来自四个渠道：

| 渠道 | 频率 | 产出 |
|------|------|------|
| 每日复盘的"卡住了" | 每天 | 知识盲区 |
| 每周复盘的"哪个方法没效果" | 每周 | 方法调整 |
| 月度复盘的 5 个问题 | 每月 | 系统级改动 |
| 认知检测结果（苏格拉底/费曼） | 按需 | 理解深度数据 |

**不需要的反馈来源**：
- ❌ "我觉得应该加一个 XX 功能"（没有数据支撑的感觉）
- ❌ "别人用的 XX 方法看起来很好"（未经你自己的实践验证）
- ❌ "我的系统是不是不够好"（这是内耗，不是反馈）
