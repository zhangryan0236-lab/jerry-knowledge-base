## 一句话定义

调试方法论是一套**系统化排查问题的思维框架**，遇到技术问题时从"瞎试"变成"有章法地排查"。

## 核心要点

### 1. 分层排查法
从下往上逐层排查，每层单独测试确认没问题再往上走：

```
第 4 层：AI 模型服务（远程服务器是否正常？）
    ↑
第 3 层：ACP 协议（适配器是否正确启动？）
    ↑
第 2 层：Node.js（运行环境是否正常？）
    ↑
第 1 层：操作系统（文件存在？路径对？环境变量配了？）
```

### 2. 二分法定位
把整个流程从中间切开，先测后半段，快速缩小范围：

```
问题：Obsidian 发消息没响应
  → 先测后半段：直接在命令行运行 opencode，看能不能和 AI 对话
  → 能：问题在前半段（Obsidian 配置）
  → 不能：问题在后半段（OpenCode 或网络）
```

### 3. 读报错信息（黄金法则）
报错信息包含三要素：
- **What**：什么出错了
- **Why**：为什么出错
- **Where**：在哪出错

### 4. 消除变量法
**每次只改一个东西**，然后测试。一次改多个→不知道哪个起了作用。

```
❌ 同时改了路径、参数、环境变量 → 好了 → 不知道哪个改对的
✅ 先改路径 → 测试 → 再改参数 → 测试 → 知道是参数的问题
```

### 5. 提问模板
```markdown
环境：Windows 11
工具：Obsidian + Agent Client Plugin + OpenCode
操作：[你做了什么]
期望：[你想达到什么效果]
实际：[实际发生了什么]
报错信息：[完整报错文字]
已尝试：[你已经试过什么]
```

## 哲学映射

调试方法论和 [[wiki/核心目标/哲学-知行合一与可证伪性]] 高度一致：
- **分层排查** = 把"系统不工作"这个大命题拆成可证伪的小命题
- **消除变量法** = 控制变量法，科学思维在编程中的直接应用
- **读报错信息** = 报错就是可证伪的证据，不是惩罚
