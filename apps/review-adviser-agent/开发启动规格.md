# 复盘军师 Agent｜开发启动规格

## 1. 本轮已确认的产品定义

这是一个以 LLM 为大脑的长期诊断军师，而不是复盘表单或通用聊天机器人。

核心闭环：

```text
复盘与资料
→ 事实切片
→ 跨期证据与候选问题
→ 当前主要矛盾（暂定）
→ 受约束知识检索
→ 微小行动与短期实验
→ 复诊
→ 个人有效性地图更新
```

军师应当比 Jerry 更系统地记住“什么条件下、什么方法、实际有效过”，而不能假装直接知道 Jerry 的内心。

## 2. 第一版范围（必须实现）

1. 接收每日流水账；
2. 只在必要时一次追问一个问题；
3. 原始内容、整理复盘和问答自动分层归档；
4. 从复盘中提取项目相关进展并同步；信息不足时只问一个进度问题；
5. 生成事实切片与证据卡；
6. 基于最近 3—7 天输出“今日信号”或“待诊断模式”；
7. 生成一个 5—15 分钟微动作与一个 1—3 天实验；
8. 在非计划日禁止改周计划，只生成明日动作。

第一版明确不做：多 Agent、自动抓取抖音、全 Vault 无差别 RAG、自动修改稳定画像、人格评分、复杂图表。

## 3. 数据优先级

```text
当前已确认事实
> 最近复盘与实验结果
> 已验证的个人有效性地图
> 经审核的干预知识卡
> 原始书籍/视频素材
> LLM 通用常识
```

每个诊断必须区分：事实、感受、Jerry 的解释、军师假设、反证/未知、待验证行动。

## 4. 受约束 RAG 规格

### 4.1 三类独立集合

| 集合 | 内容 | 权限 |
|---|---|---|
| `personal_evidence` | 事实切片、复盘、项目进度、实验结果 | 每次诊断必检索 |
| `personal_effectiveness` | 已实践方法与条件/结果 | 每次方案优先检索 |
| `intervention_cards` | 经审核的书籍、研究、博主方法卡 | 仅在问题领域匹配时检索 |

### 4.2 检索意图契约

诊断节点先产出下面 JSON，检索器只能遵守它：

```json
{
  "problem_domain": "学习过程",
  "candidate_mechanisms": ["输入多输出少", "迁移练习不足"],
  "allowed_collections": ["personal_evidence", "intervention_cards"],
  "required_card_fields": ["applicable_when", "not_applicable_when", "micro_action"],
  "time_window_days": 14
}
```

### 4.3 检索算法

```text
元数据过滤（集合、领域、审核状态、时间）
→ BM25/全文检索（术语、书名、方法名）
→ 向量检索（语义相似问题）
→ RRF 合并候选
→ 适用条件与个人有效性重排序
→ 只交付 3—5 条带来源的知识卡给 LLM
```

第一版可用 SQLite FTS5 + 本地 Qdrant。向量库仅索引整理复盘、知识卡和干预卡；原始私密文本按需读取，不做无差别上传。

### 4.4 生成门槛

LLM 只能给出同时满足以下条件的方案：

- 引用至少一个 Jerry 的日期化事实；
- 引用一张已审核知识卡，或明确说明没有足够知识依据；
- 说明适用条件与不适用条件；
- 有 5—15 分钟微动作、实验周期、指标、复诊日期；
- 若证据不足，输出“继续观察”，不输出主要矛盾。

## 5. 核心数据契约

### 事实切片

```json
{
  "date": "YYYY-MM-DD",
  "completed": [{"project_id": "", "evidence": ""}],
  "blocks": [{"event": "", "context": "", "impact": ""}],
  "state": {"energy": "unknown", "sleep_hours": null},
  "effective_conditions": [],
  "user_explanations": [],
  "tomorrow_action": ""
}
```

### 证据卡

```yaml
claim: 某项待验证观察
layer: dynamic
confidence: low | medium | high
evidence: [{date: YYYY-MM-DD, type: fact, text: ""}]
counter_evidence: []
alternative_explanations: []
next_observation: ""
expires_on: YYYY-MM-DD
```

### 干预卡

```yaml
title: 方法名
solves: []
mechanism: ""
applicable_when: []
not_applicable_when: []
micro_action: ""
duration: 1-3天
metrics: []
source: {title: "", location: ""}
status: reviewed
```

## 6. 目录与 C 盘约束

所有项目运行写入均位于：

```text
D:\Jerry的知识库\apps\review-adviser-agent\runtime\
├─ data/             # SQLite 与导出
├─ tmp/              # 临时文件
├─ cache/pip/        # pip 缓存
├─ cache/uv/         # uv 缓存
├─ cache/npm/        # npm 缓存
├─ cache/huggingface/# 本地模型缓存
└─ qdrant/           # 本地向量索引
```

正式开始前执行 `scripts/use-d-drive.ps1`。该脚本创建上述运行目录并设置当前终端的 `TEMP`、`TMP`、`PIP_CACHE_DIR`、`UV_CACHE_DIR`、`npm_config_cache`、`HF_HOME`、`QDRANT_PATH`。

若将来某个工具不能被这些变量重定向，必须先向 Jerry 说明它会写入 C 盘的具体位置，再执行。

## 7. 正式开发顺序

1. FastAPI 健康检查与 D 盘运行配置；
2. LangGraph 复盘问答暂停/恢复；
3. Markdown 自动归档；
4. 事实切片和项目同步；
5. 证据卡与 3—7 天趋势；
6. 受约束 RAG 的知识卡检索；
7. 微实验、复诊与计划守卫；
8. 驾驶舱界面接 API。
